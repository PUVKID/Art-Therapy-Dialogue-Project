## 프로젝트 소개

시각 모델과 언어 모델을 탐지 요약 인터페이스로 연결한 설계입니다. 원고의 상담 입력 결합과 공개 앱의 독립 그림·질문 호출은 차이가 있습니다. 통합 보고서가 생긴다는 사실과 임상적 타당성은 별도 문제입니다.

### LEVEL 4 · 연구와 앱의 네 단계

| 대상·조건 | 동작과 의미 |
| --- | --- |
| 명시된 설정·조건 | **실제 조건:** 그림 입력 → 객체 탐지 → 대화 메시지 → PDF 보고서. |
| 그림 입력·분석 | 앱의 그림 분석과 텍스트 질문은 별도 요청입니다. |

analyze_and_suggest와 ask_gpt는 서로의 상태를 이어 받는 대화 파이프라인이 아닙니다.

원고의 통합 설계를 구현하려면 탐지 요약·사용자 입력·이력을 전달하는 별도 상태 경계가 필요하며 현재 구현에 있다고 기술하지 않습니다.

### LEVEL 4 · 합성 자료와 학습 횟수

| 대상·조건 | 동작과 의미 |
| --- | --- |
| 명시된 설정·조건 | **실제 조건:** 33 클래스 × 클래스당 10,000장 = 330,000장. |
| 합성 이미지 구성 | 중앙의 단일 객체와 색상 변형. |
| 원고 학습 설정 | 원고: YOLOv8n, 50 epoch × 100 단계. |
| 학습 경로·범위 | 연결된 학습 코드는 30 단계이며 resume_flag를 호출에 넘기지 않습니다. |

원고의 단계별 누적 학습과 스크립트의 반복 호출은 체크포인트·재개 인자 연결까지 같아야 대응됩니다.

50×100은 구성상의 합계이고 독립 학습 100회나 5,000개의 독립 검증을 뜻하지 않습니다.

실제 초기화와 가중치 계승을 확인하기 전에는 코드와 원고의 동일성을 주장하지 않습니다.

### LEVEL 4 · 손실과 탐지 지표

| 구분 | 지표 | 원고 보고값 |
| --- | --- | ---: |
| 손실 | box loss | 0.38 |
| 손실 | classification loss | 0.28 |
| 손실 | DFL | 0.81 |
| 탐지 지표 | mAP50 | 0.92 |
| 탐지 지표 | mAP50–95 | 0.78 |

**평가 조건:** 학습·검증 자료가 같습니다.

세 손실의 절대 값을 서로 우열 비교하거나 mAP의 직접 원인으로 단정하지 않습니다.

평가 누수와 실제 사용자 그림의 도메인 차이를 통제한 실험이 없으므로, 낮은 손실과 높은 적합도를 임상적 유효성이나 배포 성능으로 확장하지 않습니다.

### LEVEL 4 · 평가 배열과 기술통계

각 평가 배열은 **32개**입니다.

| 평가 항목 | 3점 개수 | 4점 개수 | 5점 개수 |
| --- | ---: | ---: | ---: |
| 정서 적절성 | 2 | 10 | 20 |
| 자연스러움 | 1 | 5 | 26 |
| 공감 | 2 | 12 | 18 |

**기술통계:** 평균·중앙값·표준 편차 ddof =1·25/75 분위수.

ddof =1 과 사분위수 계산은 통계 추정의 선택입니다.

세 배열이 대응 표본인지, 응답자 식별과 수집 절차가 연결되는지는 별도 근거가 필요합니다.

빈도 배열의 그래프를 통계적 유의성 검정이나 임상 효능 평가로 바꾸어 해석하지 않습니다.

### LEVEL 4 · 이미지 저장과 탐지 입력

| 자료·처리 경계 | 입력과 출력의 관계 |
| --- | --- |
| 명시된 설정·조건 | **실제 조건:** NumPy RGB → OpenCV BGR → input/temp.jpg. |
| 추론 입력·출력 | 추론 conf=0.05, imgsz=640. |
| 이미지 저장과 탐지 입력 | 상자 존재 여부와 분석 시각만 요약합니다. |

has_det는 상자 개수의 불리언 축약입니다.

색 변환 실패·파일 쓰기 실패·YOLO 오류를 API 예외 처리와 분리해야 합니다.

특히 cv2.imwrite 반환 값을 확인하는 방어가 없고 임시 파일 경로가 고정이므로 저장 실패와 동시 호출이 분석 출처를 어긋나게할 수 있습니다.

### LEVEL 4 · 언어모델과 실패 흐름

| 확인 단계 | 할 일과 확인 조건 |
| --- | --- |
| 명시된 설정·조건 | **실제 조건:** gpt-4o-mini에 system/user 두 메시지. |
| 그림 입력·분석 | 그림 분석은 10~15 문장 요청. |
| 독립 질문 요청 | ask_gpt는 입력 질문만 별도 전송. |
| API 요청·실패 | API 예외는 오류 문자열로 반환, 그림 분석은 이어서 PDF 생성을 시도합니다. |

try/except의 범위는 외부 언어 모델 요청에 한정됩니다.

이미지 색 변환·YOLO 추론·build_pdf의 오류는 그 경계 밖이고, API 오류 문자열이 정상 보고서 내용으로 흘러갈 수 있습니다.

실행 상태와 출력 유효성을 별도 검증해야 합니다.

### LEVEL 4 · 실행 환경과 출력 파일

| 구성·역할 | 처리와 확인점 |

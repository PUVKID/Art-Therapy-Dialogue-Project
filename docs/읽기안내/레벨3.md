<a id="guide-problem"></a>

## 문제와 주요 기능

원고 단계별 질문·제목·평가 설명의 변화를 대조합니다. 1차의 우울증 대상 구상에서 3차의 그림 심리 분석 시스템 설계·구현으로 범위가 정리됩니다. 제목·서술 개정이 독립 임상 실험의 추가를 뜻하지 않습니다.

<a id="guide-flow"></a>

## 입력·처리·출력

공개 앱의 conf0.05·imgsz640, RGB→BGR 저장과 모델 요청 본문을 확인합니다. 실제 언어 모델 입력은 탐지 성공·실패와 시각의 요약입니다. 원고의 상담 문맥 결합 설계와 같은 호출이라고 가정하지 않습니다.

<a id="guide-practice"></a>

## 실험과 사용 흐름

원고의 방법 →공개 앱 함수 →점수 배열·통계 →실제 결과의 한계 순으로 대조합니다. 그림 5 노트북은 응답자 파일을 읽지 않고 항목별 32점 분포를 코드에서 만듭니다. Colab용 폰트·다운로드와 로컬 저장 경로도 구분합니다.

## 구현과 핵심 파일

## LEVEL 3 · 조건과 결과를 자세히 읽기

아래 조건은 원고·공개 노트북에 있는 값입니다. 차수별 상세는 각 단계의 기록이며, 최신 원고의 설정을 이전 차수에서 새로 얻은 결과로 소급하지 않습니다.

### LEVEL 3 · 연구와 앱의 네 단계

**실제 조건:** 그림 입력 → 객체 탐지 → 대화 메시지 → PDF 보고서. 앱의 그림 분석과 텍스트 질문은 별도 요청입니다.

그림 분석 버튼에서 이미지·메시지·보고서 세 출력을 확인하고 질문 버튼은 따로 시험합니다. 앞선 그림이나 대화가 다음 요청에 자동으로 포함되는지 기대하지 않고 실제 messages 구성과 대조합니다.

### LEVEL 3 · 합성 자료와 학습 횟수

**실제 조건:** 33 클래스 × 클래스당 10,000장 = 330,000장. 중앙의 단일 객체와 색상 변형. 원고: YOLOv8n, 50 epoch × 100 단계. 연결된 학습 코드는 30 단계이며 resume_flag를 호출에 넘기지 않습니다.

원고 실험을 재현하려면 먼저 클래스 수·종류별 개수·중앙 배치·색상 변형을 맞춥니다. 다음으로 50 epoch와 100 단계가 실제 실행 로그에서 어떻게 이어지는지 확인합니다. 연결된 스크립트의 30 단계와 미전달 resume_flag를 확인하고, 기존 결과 없이 완료된 학습으로 기록하지 않습니다.

### LEVEL 3 · 손실과 탐지 지표

**실제 조건:** 원고 보고값: box loss 0.38 / classification loss 0.28 / DFL 0.81 / mAP50 0.92 / mAP50–95 0.78. 학습·검증 자료가 같습니다.

결과를 비교할 때 손실 세 항목과 두 mAP의 이름을 함께 기록합니다. 동일한 평가 자료·겹침 기준·모델 판본을 맞추고, 학습에 사용한 자료와 분리된 시험이 있는지 확인합니다. 이 원고의 값은 저장된 보고값이며 새 평가를 실행한 수치로 바꾸지 않습니다.

### LEVEL 3 · 평가 배열과 기술통계

**실제 조건:** 각 32개: 정서 적절성 3점 ×2·4점 ×10·5점 ×20/자연스러움 3점 ×1·4점 ×5·5점 ×26/공감 3점 ×2·4점 ×12·5점 ×18. 평균·중앙값·표준 편차 ddof =1·25/75 분위수.

세 배열 길이와 빈도 합계를 먼저 확인한 뒤 np.mean·np.median·np.std(ddof=1)·np.percentile(25/75)을 실행합니다. 자료를 교체하면 값과 그림을 함께 다시 만듭니다. 원응답 파일을 읽은 것으로 보고하지 않고 코드 입력을 사용한 기술통계라고 기록합니다.

### LEVEL 3 · 이미지 저장과 탐지 입력

**실제 조건:** NumPy RGB → OpenCV BGR → input/temp.jpg. 추론 conf=0.05, imgsz=640. 상자 존재 여부와 분석 시각만 요약합니다.

입력 배열을 저장한 뒤 temp.jpg 생성과 모델 경로를 확인합니다. 같은 conf =0.05와 imgsz =640에서 실행하고 결과 상자 수가 0인지 구분합니다. 반환 화면은 원본 RGB 이미지이며, 탐지 상세 좌표가 대화 입력에 포함된 것으로 오해하지 않습니다.

### LEVEL 3 · 언어모델과 실패 흐름

**실제 조건:** gpt-4o-mini에 system/user 두 메시지. 그림 분석은 10~15 문장 요청. ask_gpt는 입력 질문만 별도 전송. API 예외는 오류 문자열로 반환, 그림 분석은 이어서 PDF 생성을 시도합니다.

환경 변수 OPENAI_API_KEY를 먼저 설정하고 각 버튼을 따로 확인합니다. API 실패 문자 열과 정상 응답을 구분하며, 보고서 파일이 생겼다는 이유만으로 분석 전체가 성공했다고 판단하지 않습니다. 이미지·모델·폰트·출력 오류는 발생한 단계에서 확인합니다.

### LEVEL 3 · 실행 환경과 출력 파일

**실제 조건:** Gradio·Ultralytics·fpdf2·OpenAI·OpenCV. 모델·작업·폰트 경로 필요. 고정 result/report.pdf, A4·여백 15mm·이미지 x10/w90mm·글자14/11/12. 평가 PNG 600dpi, Colab 폰트 설치·다운로드 셀.
